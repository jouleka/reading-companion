# LIT-8 spike — spoiler-leak eval harness

Proves spoiler-safety **end to end** across the three leak vectors + recap-cache coherence. Reuses
the LIT-5 store (ADR 0002) and the LIT-6 extraction artifacts (ADR 0003). The store's own
`revealed_at` stamps are the **automatic ground truth**: at bookmark `B`, the forbidden set is
exactly `{fact : revealed_at > B}`, so a leak = any output surfacing a forbidden fact.

## Run

```bash
python3 spikes/lit-8-spoiler-eval/harness.py        # deterministic eval (structured + RAG + cache)
python3 spikes/lit-8-spoiler-eval/harness.py dump-facts   # writes synth_facts.json for the synth workflow
python3 spikes/lit-8-spoiler-eval/synth_measure.py  # synthesis over-reach (needs synth_results.json)
```

## The four vectors

| # | Vector | Guarantee / mechanism | Result |
|---|---|---|---|
| 1 | **Structured reads** | **all** `BookmarkView` read methods (incl. `aliases_of`, `current_state`, `events_for`, `bio`, `raw_text`, `catch_me_up`), every bookmark — no returned row or *referenced* entity has `revealed_at > B`. Falsifiable: Zossima rev4 hidden@2/appears@4, **and** dropping the alias filter makes the harness report 6343 leaks | **1877 reads, 0 leaks** |
| 1b | **Reveal-correctness** | independent of the DAL filter (defeats circular ground truth): each named entity's name first appears in **prose** by its `revealed_at` chapter | **27 entities, 0 mis-stamps** |
| 2 | **RAG / quote path** | `search()` never returns a chunk with `revealed_at > B`. In-text foreshadow inside an *already-read* chunk is **reader-parity-safe** — flagged, not failed; residual = sub-chapter granularity → **LIT-12** | 60 retrievals, **0 leaks** (36 foreshadow chunks flagged) |
| 3 | **Synthesis over-reach** | grounded-only prompt + **deterministic** future-entity-name check (case-insensitive; surname- & reader-parity-safe) + **prolepsis** future-tense tripwire + **LLM-judge** (hard on `references_future`, soft on paraphrase). **Limit:** a future event in past tense with no name → only the soft judge (deterministic NLI gate routed) | **0 hard leaks / 0 prolepsis / 0 future-refs**; 11 soft over-reach claims surfaced |
| 4 | **Recap-cache coherence** | cache key = `(book_id, bookmark, validity_snapshot)`; the snapshot hashes the live set across **all** fact tables with a **content fingerprint** (`recorded_at`), so a retroactive `invalid_at`, a re-extraction (retraction OR in-place rename), a new alias, or a re-chunk flips the key → cache miss | snapshot changes on retraction, retroactive `invalid_at`, in-place re-extraction ✓ |

## Why the metric is honest

- **Falsifiable, not a no-op:** the harness proves it can FAIL — a name-like late entity (Zossima) is
  hidden at an earlier bookmark and appears at its reveal chapter, and the synthesis scorer **catches a
  planted future-entity leak** ("the elder Zossima" injected at bookmark 2).
- **Surname-safe:** a token shared with a visible entity (e.g. "Karamazov", visible via Fyodor@1) is
  NOT counted as a leak even though "the Karamazov family" appears later — only tokens *exclusive* to
  future entities are forbidden.
- **Reader-parity for RAG:** returning a chunk the reader has fully read can't spoiler them; the real
  RAG residual is sub-chapter position (LIT-12) and synthesis elaboration (vector 3), both routed.

## Honest scope / routed

- Synthesis recaps were generated by a strong **book-aware** model (no cheap backend in the env) — the
  hard future-entity check is model-tier-independent, but cheap-tier over-reach behaviour is unproven
  (→ LIT-20). The LLM-judge is itself an LLM (judge error is possible) — paired with the deterministic
  check it is a hybrid, per the ticket's leaning.
- Sub-chapter spoiler frontier (a chunk read only partway) → **LIT-12**.
- Sample = 5 Karamazov chapters; broader corpus / book types → LIT-9.
