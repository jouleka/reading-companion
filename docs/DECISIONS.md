# Decision log

Running log of decisions. Each substantial research spike should add or refine an entry here and,
when appropriate, a full ADR in [`adr/`](adr/). Historical `LIT-*` identifiers are retained only as
stable cross-references.

Status legend: **Accepted** (decided) · **Provisional** (leaning, to be confirmed by a spike) · **Superseded**.

---

### D1 — Product concept: spoiler-safe reading companion ("reader with a brain") — **Accepted** (2026-06-25)
A web app that is also an EPUB reader; builds a growing, spoiler-safe **memory of the user's own reading**. Not a summarizer. Solves: come back to a long book after a break without being lost or spoiled.

### D2 — Store a memory, not the book; incremental & bookmark-bounded — **Accepted** (2026-06-25)
Process each chapter once (append-only), only up to the bookmark. Never holds the whole book in context → solves token/context limits **and** makes spoilers impossible at the source. *Rejected:* read the whole book then gate (blows context + secretly knows the ending).

### D3 — Spoiler-safety by construction (bitemporal stamps) — **Accepted** (2026-06-25)
Every fact/edge/event stamped `revealed_at`; `invalid_at` for superseded facts. All reads filter `revealed_at <= bookmark AND (invalid_at IS NULL OR invalid_at > bookmark)`. Enables time-travel to earlier chapters. (Graphiti/Zep bitemporal pattern.)

### D4 — Entity resolution: canonical + aliases + embedding match + running roster — **Provisional** (2026-06-25)
One canonical record per entity with alias list; cosine-match new mentions (iText2KG); feed running cast roster into extraction prompt. *Thresholds and Russian-name handling to be set by a spike.*

### D5 — Two model tiers + prompt caching — **Accepted** (2026-06-25)
Cheap/small (or local) model for per-chapter extraction; large model only for synthesis (recaps/notes), lazily; prompt-cache the stable recap prefix. *Exact models to be chosen by a spike.*

### D6 — Storage: SQLite + sqlite-vec; RAG bookmark-bounded; LanceDB scale-up — **Accepted** (2026-07-14)
One SQLite memory file per book; canonical JSON vectors support portable recovery and exact brute-force cosine. Production KNN uses sqlite-vec 0.1.9 with book, reveal, retraction, live-chapter, and embedding-space metadata constrained **before** ranking. LIT-26 found zero real recall losses (one float32 boundary tie); LIT-34 adopted the guarded virtual table with exact shadow classification and fail-closed schema/parity checks. Brute force remains the reference/fallback. Version 0.1.9 scans within the filter, so no sublinear claim is made; LanceDB remains a possible future scale-up.

### D7 — Four views; MVP pair = catch-me-up + character graph — **Accepted** (2026-06-25)
Views: catch me up (hero), character graph (with bookmark scrubber), timeline (swimlanes), chapter notes. Build catch-me-up + character graph first.

*Implementation amendment:* the graph requirement evolved into the structured Codex relationship ledger in D22; the bookmark-bounded relationship view and scrubber remain.

### D8 — Form factor: in-app EPUB reader, web first, stand on existing engine — **Accepted** (2026-06-25)
Read in-app (split pane) so position is automatic. Use a mature EPUB reader engine (epub.js/Readium/foliate-js — *choice is a spike*). Web first; API split for future mobile.

### D9 — Import policy & DRM boundary — **Accepted** (2026-06-25)
Allowed: DRM-free EPUB (file/drag) + one-tap public-domain (Gutendex/Standard Ebooks). Partial/later: Kindle highlights (~10%). Forbidden: importing DRM-locked purchases (DMCA §1201) — do not build.

### D10 — Stack: Python/FastAPI + TS/React + Cytoscape; pluggable LLM; web now, mobile later — **Accepted** (2026-06-25)
Bottleneck is LLM latency, not CPU → Python over Rust. LLM behind a one-function interface (BYO-key / hosted-sub / local).

*Partially superseded by D22:* Python/FastAPI, React, and the pluggable LLM boundary remain; Cytoscape was removed from the shipped Codex.

### D11 — Process: research spikes first → ADR per spike → then build — **Accepted** (2026-06-25)
Validate the best approach for every subsystem before building; each spike ends in a recorded decision; keep spec + this log + research current so no context is lost.

### D12 — Productization later (BYO LLM / hosted sub) — **Provisional** (2026-06-25)
Personal-first → others via own LLM key or paid sub using owner's hosted LLM; multi-tenant + billing later. v1 architecture must not foreclose it.

### D13 — EPUB chapter segmentation algorithm (LIT-4) — **Accepted** (2026-06-25)
Chapters derive from OPF spine + ToC (EPUB3 nav / EPUB2 NCX), classified by **explicit signals only, never position**: front = nav/guide/cover/toc/PG-header/Contents; back = a PG-license doc *without* a chapter label; body = the rest. Granularity = file-driven (1 spine doc = 1 chapter) unless leaf ToC navPoints ≫ body files → anchor-driven split at fragments. Hierarchical ToCs use **leaf** nodes (scenes, not Act+Scene). Empirically validated on 5 real EPUBs (Karamazov 97, Hamlet 20 scenes, P&P 60, Holmes 12, Frankenstein 28) with no front-matter cast-list leak. Defines the `revealed_at` chapter atom + chapter-key that D3 / LIT-5 / LIT-12 depend on. Full record: [`adr/0001-epub-chapter-segmentation.md`](adr/0001-epub-chapter-segmentation.md).

### D14 — Multi-book storage: per-book SQLite file + global catalog DB (LIT-18) — **Accepted** (2026-06-26)
One `memory.db` **per book** + one small global `catalog.db`. Per-file = **physical isolation** (a KNN/SELECT cannot cross books — not a `WHERE` we might forget), plus trivial per-book backup/export/delete and per-book write concurrency (WAL). `catalog.db` holds the shelf, the **mutable reading state** (`bookmark`/`cfi`/`ingest_progress`), and `cost_ledger`. `book_id` is still carried on every fact row as a reserved hook so the same DAL survives a future single-DB/multi-tenant collapse. *Rejected:* one DB with `book_id` everywhere now (makes the spoiler+isolation filter forgettable). Full record: [`adr/0002`](adr/0002-bitemporal-schema-and-dal.md).

### D15 — Raw-text retention: retain bookmark-bounded raw chapters, local-only, version-stamped (LIT-19) — **Accepted** (2026-06-26)
Retain raw chapter text up to the bookmark **locally** as ground truth → enables RAG quote answers + **cheap re-extraction** when the prompt/model/schema improves, without re-opening the user's file. It is the user's own legally-imported content (D9), **local-first only**; any hosted/synced retention is explicitly gated behind a future policy (LIT-24). Read through the spoiler funnel (`view.raw_text()`), never only the audit hatch. Migration = `schema_version`/`extractor_version` stamps + transaction-time supersession; mixed versions coexist; idempotent re-ingest. Full record: [`adr/0002`](adr/0002-bitemporal-schema-and-dal.md).

### D16 — Bitemporal schema + spoiler-safe DAL (LIT-5) — **Accepted** (2026-06-26)
**Two temporal axes:** valid-time (`revealed_at`/`invalid_at`, in chapter ordinals → the spoiler filter + time-travel) and transaction-time (`schema_version`/`extractor_version`/`recorded_at`/`retracted_at` → re-extraction/audit, forced by D15). Typed bitemporal tables; the **bookmark is an integer passed into `view(bookmark)`**, not stored in `memory.db`. Spoiler-safety is structural via a DAL whose filter is centralized in ONE funnel, enforced by a **per-connection SQLite authorizer** (a raw fact read is denied), and made **referentially closed** (entity-referencing reads semijoin the visible-entity set; chunk/summary reads semijoin live chapters) so no read can surface an unmet entity. Validated by a 31-check executable proof + **two** adversarial Opus passes — the first caught a referential spoiler-leak **BLOCKER**, now fixed and re-proven. Full record: [`adr/0002`](adr/0002-bitemporal-schema-and-dal.md).

### D17 — Two-tier extraction pipeline + cast-roster entity resolution (LIT-6) — **Accepted** (2026-06-26, empirically closed out)
Per-chapter **cheap-tier** extraction receiving the bookmark-bounded running roster → layered resolution (roster-link → exact → name-like-alias → margin-gated embedding) → write through the LIT-5 store (append-once via content_hash, `extractor_version`-stamped); **large tier** reserved for lazy recap/notes synthesis. Output is a schema-validated JSON object mapping field-by-field onto the LIT-5 tables (chapter ordinal → `revealed_at` at ingest). A **provider-agnostic** one-function LLM/embedding interface (Anthropic / any OpenAI-compatible / offline stub; raw HTTP, no SDK) — concrete groundwork for [[LIT-20]]. Validated live on Karamazov Book I ch I–V via the agent harness: resolution **P/R 1.00 on 10 gold main-cast clusters** with a now-**falsifiable** metric (over-merge scanned across all entities, fragmentation, coverage floor) + **98.8% name-grounding** + append-once; ~1.5¢/chapter (lower bound). Two adversarial passes (rev1 MORE_WORK → rev2 FIX_THEN_ACCEPT) fixed a non-falsifiable metric, a PENDING-id ingest crash, and several real over/under-merge bugs. **EMPIRICAL CLOSE-OUT (2026-06-26, real `gpt-4o-mini` + `text-embedding-3-small` via the LIT-20 interface — `close_out.py`):** cheap-tier resolution **P/R = 1.00** on the gold main cast, **96.9% name-grounding**, **~$0.10 for the whole 97-chapter book** (real token usage); paraphrased-fact spoiler-safety closed via [[LIT-8]] (judge hard-gate caught a real forward-framing over-reach → anti-foreshadow prompt + gate → clean). **One honest residual:** cheap-tier extraction *recall* (`gpt-4o-mini` missed a major character, Zossima) — a model/prompt-tuning matter (stronger cheap model / recall prompt / second pass), not an architecture gap; routed to the build + [[LIT-9]]. Full record: [`adr/0003`](adr/0003-extraction-and-entity-resolution.md).

### D18 — Spoiler-leak eval harness (LIT-8) — **Accepted** (2026-06-26)
A **hybrid** eval harness proving spoiler-safety end-to-end across four vectors — the gate for the MVP views and LIT-6's close-out. The store's own `revealed_at` stamps are the automatic ground truth (forbidden@B = `revealed_at > B`). (1) **Structured reads** — every BookmarkView method × every bookmark, no row/referenced-entity past B (1877 reads, 0 leaks; falsifiable — dropping a table's filter yields 6343 leaks). (1b) **Reveal-correctness** — independent of the DAL filter: each name first appears in prose by its `revealed_at` (defeats the circular ground truth; 0 mis-stamps). (2) **RAG** — `search()` never returns a future chunk (0 leaks); in-text foreshadow in already-read prose is reader-parity-safe; sub-chapter → [[LIT-12]]. (3) **Synthesis over-reach** — grounded-only prompt + deterministic future-entity (case-insensitive, surname/reader-parity-safe) + prolepsis future-tense tripwire + LLM-judge (hard on references_future, soft on paraphrase); 0 hard leaks on 3 real recaps, 11 soft over-reach claims surfaced. (4) **Cache coherence** — key=(book_id, bookmark, validity_snapshot) hashing the live set across all fact tables + a content fingerprint, so retroactive `invalid_at`, retraction, in-place re-extraction, new alias or re-chunk all flip the key. Survived an adversarial Opus review (FIX_THEN_ACCEPT) that found the synthesis gate was blind to past-tense no-name future EVENTS + lowercased names + coverage/cache/circularity gaps — all fixed. **Accepted for the harness**; the production spoiler verdict it computes is measured-risk: a past-tense no-name future event rests on the soft judge (deterministic NLI gate → build), and cheap-tier synthesis → LIT-6/[[LIT-20]]. Full record: [`adr/0004`](adr/0004-spoiler-leak-eval-harness.md).

### D19 — Pluggable LLM/embedding interface + provider/model versioning (LIT-20) — **Accepted** (2026-06-26)
ONE tier-aware provider-agnostic interface (`complete`/`embed`/`version`; backends anthropic / any openai-compatible / stub; raw HTTP, no SDK) — finalizing LIT-6's `llm.py`. The **embedding backend is configured INDEPENDENTLY** of completion (`EMBED_*` env), because Anthropic has no embeddings API; `embed()` never lies — a stub fallback warns + stamps `stub:lexical-stub-256`, never a configured name. **PIN the extractor+embedding model per book at first ingestion** (`book_meta`); the embed identity = full `provider@base_url:model` + dim + a **cosine-compared canary** (catches a same-NAME space change while tolerating a real embedder's run-to-run float noise). **Enforced, not advisory:** every vector carries its embed model/dim, `add_chunk` rejects a vector ≠ the pin, `search` is same-space by default. **Safe-swap matrix:** synth/large may change freely (recap cache keys on it); extractor → re-extract; embed model/dim/weights → re-embed (`repin_embedding` overwrites in the migration); schema → migrate. Validated by an executable proof; survived **two** adversarial Opus passes (pass 1: 2 BLOCKERs — embed/completion conflation + bare-name safe_swap; pass 2: canary-determinism + late-pin recall hole — all fixed). Schema delta applied to LIT-5 (chunks `embed_model`/`embed_dim`; book_meta pinned cols + `embed_canary`); LIT-5/6/8 suites green. Unblocks LIT-6 close-out (pin a real cheap + embedding model, re-run the LIT-6/8 harnesses). Full record: [`adr/0005`](adr/0005-llm-embedding-interface-versioning.md).

### D20 — Sub-chapter spoiler frontier (LIT-12) — **Accepted** (2026-06-26)
The reader's continuous CFI (usually mid-chapter) maps to the LIT-5 DAL's **integer bookmark = the number of chapters FULLY completed**; the chapter under the CFI is held **pending** (its facts, stamped `revealed_at`=its ordinal, are filtered because bookmark < that ordinal). Whole-chapter-on-completion (never on-entry) → the unread remainder can't surface; accepts a bounded one-chapter **lag** (the just-read prefix isn't recapped until the chapter completes — fine for a catch-me-up tool). Preconditions ENFORCED (not assumed): (1) the frontier's geometric ranges map **1:1 onto the DAL's `revealed_at` atoms** — `assert_aligned` checks count + contiguity 1..N (catches an unmerged-divider drift); (2) **no zero-length atom** (`chapter_bounds` rejects it — a degenerate atom would be "complete" yet never pending → leak; the ADR-0001 divider-merge must run upstream); (3) **monotonic-forward** high-water bookmark (backward paging never un-reveals; re-read = [[LIT-17]]). Position is modeled as a monotonic char-offset, order-isomorphic to a CFI for the only ops the frontier needs (compare + locate-in-range); the real reader (LIT-13) supplies the CFI comparator. A **sub-chapter upgrade** (`subchapter_visible`, fact_subpos=span END in a normalized fraction-through-chapter space) removes the lag without leaking — routed to LIT-6 (fact stamping) if the lag bites. Validated by a 20-check proof + a 99-position probe grid against the real store (0 leaks); two adversarial Opus passes (pass 1: zero-length + divider-drift HIGH leaks + circular proof; pass 2: alignment-guard identity + count). Full record: [`adr/0006`](adr/0006-subchapter-spoiler-frontier.md).

### D21 — Backend service architecture (productionize the cores into a FastAPI service) — **Accepted** (2026-06-28; two adversarial Opus passes)
Step A of the MVP build. ONE `backend/` package, subsystem-per-module. Honest two-tier reuse: the pure spoiler-critical cores (`_select` funnel, `_authorizer`, referential closure, `score_recap`/`validity_snapshot`, the resolver, the frontier, the explicit `FACT_TABLES` set) are **lifted near-verbatim**; `llm/client.py`, `memory/vectors.py`, and the ingestion pipeline are **re-ported with named, behaviour-relevant changes** (not "verbatim"). Key decisions: (1) **per-book `Store` is the sole owner of each `memory.db` connection, opened `check_same_thread=False` and accessed under a per-book `threading.Lock` held for the WHOLE operation** (the whole `with store.book(id) as view:` render, not per-statement) — closes the `_engaged` concurrency bypass (different books parallel, same book serialized; reads + the ingestion worker share the lock; LRU eviction is lease/lock-coupled); (2) **ship the PROVEN brute-force cosine path with the spoiler FILTER kept inside `BookmarkView.search` and `vectors.py` as a no-DB ranker only; gate the `sqlite-vec` `vec0` swap on a dedicated recall + shadow-table spike** — don't build core spoiler-safe retrieval on unproven `vec0`; (3) fast reads sync-under-lock, **slow per-chapter ingestion off the request path** in a serialized threadpool worker that does LLM work OUTSIDE the lock (LIT-7/22); (4) LLM via the **openai SDK's native strict structured-output helper + Pydantic models as the schema source of truth → dict downstream via `model_dump(mode="json")`** (pipeline/gate dict-contract unchanged), provider-agnostic via `base_url` with an honest per-provider matrix + Pydantic-validate backstop, embeddings configured independently (LIT-20), offline stub + `embed()`-never-lies kept; **Instructor deferred/optional**; (5) **forward-only versioned migration runner** (no Alembic), one create-path (stamp v1 → walk to CURRENT), and an **explicit, fail-closed `FACT_TABLES` that INCLUDES `book_meta`** asserted ⊇ all `revealed_at`-bearing tables at open (deriving the set from the schema was rejected — it fails open); append-once is DB-enforced by partial-UNIQUE indexes on the **derived** tables + a pipeline early-return; (6) `pydantic-settings` reading the git-ignored repo-root `.env` via an absolute `__file__`-derived path, fail-loud (default-deny `ALLOW_STUB`); (7) **implement the ADR-0001 `<200`-word divider-MERGE for real** — the merged atom **absorbs the divider's start anchor**, Part captured in the existing **`part_label`** column — so LIT-12 alignment holds on Karamazov; (8) the **spoiler gate is a first-class app package shared by runtime synthesis AND wired into CI** as a merge gate, with the runtime `score_recap` pinned to `read_text` of chapters `<= effective_bookmark`; (9) **reading position = the high-water CFI is canonical, the integer bookmark is its monotonic derived projection** (stamped with an atom-set version, re-derived `max(re_derived, prior)` on any renumber, **fail-closed** on version mismatch), and the **scrubber bookmark is clamped server-side** to the version-current high-water on every bookmark route; (10) `catalog.db` (the only un-isolated shared writer) gets a global lock + `busy_timeout` + a monotonic-`MAX` `ingest_progress`. Survived pass 1 (5 reviewers; 3 BLOCKER-class) and pass 2 (4 reviewers re-attacking the fixes; caught genuine regressions the pass-1 fixes introduced — append-once-on-wrong-table, `book_meta` dropped from the guarded set, `model_json_schema`≠OpenAI-strict, an unspecified runtime gate `read_text` — all fixed). Routed: `vec0` recall spike, deterministic NLI event-grounding gate, cheap-tier recall tuning, LIT-7/22/24 hardening. Full record: [`adr/0007`](adr/0007-backend-service-architecture.md).

### D22 — Structured Codex is an editorial relationship ledger, not a canvas graph (LIT-31) — **Accepted** (2026-07-08; reconciled 2026-07-13)
The detailed Codex is a bookmark-bounded reading aid built from semantic DOM: chapter orientation, a searchable people index, relationship summaries, evidence threads, and a shared chapter scrubber. The earlier Cytoscape/`FocusGraph` prototype was retired in favour of `PeopleConnections`, which is easier to scan, works without canvas semantics, and keeps the same spoiler boundary. The people list owns an explicit roving tab stop (Arrow keys/Home/End, Enter/Space to select), while search and scrubber retain their own focus. Structured Codex reads remain available even if optional recap synthesis fails.

### D23 — Chapter completion is an atomic durable receipt; markerless stores are rebuilt (LIT-7) — **Accepted** (2026-07-08; reconciled 2026-07-13)
Each chapter's derived writes and `ingested_chapters` completion marker commit in one transaction, with the marker written last. Resume starts from the contiguous completed frontier and never promotes `ingest_progress` or bookmark state alone into proof of completion. Pre-LIT-7 stores have no trustworthy per-chapter receipts, so current code clamps their effective bookmark to zero; operators must preserve the original assets and rebuild into a fresh data directory rather than mutating or guessing completion.

### D24 — Process-local memory is bounded and shelf-incarnation aware (LIT-33) — **Accepted** (2026-07-13)
The Store retains a configurable number of per-book SQLite handles in access order. A reference-counted lease covers holders and waiters, so only idle handles can be evicted; temporary overflow is allowed while every candidate is active and converges on release. EPUB segmentation is a bounded LRU keyed by `(book_id, catalog_incarnation)`. Successful recaps, negative gate results, and distinct active single-flights have independent bounds; recap keys include book id, catalog incarnation, bookmark, validity snapshot, pinned synthesis model, prompt version, and atom-set version. Shelf deletion explicitly closes the Store handle and invalidates segmentation/recap state but preserves the on-disk source and memory files for the separate LIT-24 policy.

### D25 — Backup/export is a verified per-book dual-format archive; restore is staged and atomic (LIT-24) — **Accepted** (2026-07-13)
One `.rcbackup` contains SQLite online-backup snapshots, a portable table/column-described JSON export, `source.epub`, and `atoms.json`, with member hashes and no credentials. Verification binds catalog identity/incarnation/reading state/costs to `book_meta`, source hash, atom set, current schema, and the contiguous LIT-7 receipt frontier. Restore verifies into a sibling stage and atomically publishes a whole data directory; collisions fail closed, explicit same-book replacement retains a rollback directory, and the app/restore share a cross-process data-directory lock. Per-book archives do not replace or merge a multi-book library. Full record: [`adr/0009`](adr/0009-backup-export-and-recovery.md).

### D26 — Provider spend is pre-reserved; huge chapters are request-chunked, not atom-split (LIT-21) — **Accepted** (2026-07-13)
Each completion atomically reserves conservative input, capped output, and known-model USD against per-book ledger-plus-reservation ceilings before provider I/O. Reservations survive crashes and require explicit conservative reconciliation; successful extraction chunks settle through the one LIT-7 chapter receipt. Oversized chapter text is split losslessly at prose boundaries for provider calls, validated, and merged while retaining one memory/spoiler atom. Token ceilings protect unknown prices; USD remains advisory rather than fabricated. Full record: [`adr/0010`](adr/0010-cost-ceilings-and-huge-chapters.md).

### D27 — EPUB import is bounded and fails closed on archive ambiguity or DRM (LIT-11) — **Accepted** (2026-07-13)
The upload body and exact file are bounded before publication; ZIP member count, per-entry/total expansion, compression ratio, compression method, canonical path identity, duplicate/case collisions, symlinks, exact reads, manifest ids, and spine resolution are validated before segmentation. ZIP/content encryption is rejected with an explicit DRM-free message, while standard IDPF/Adobe font obfuscation is allowed only for existing font targets. Imperfect chapter markup remains recoverable. ToC-referenced `linear="no"` items are retained and flagged; other non-linear items are excluded and flagged. Full record: [`adr/0011`](adr/0011-adversarial-epub-ingress.md).

### D28 — Explicit high-consequence event roles are deterministically bound to visible entities (LIT-27) — **Accepted** (2026-07-13)
After lexical grounding, each explicit name-bearing high-consequence recap claim must bind the same visible entity, event family, and agent/patient role as a bookmark-bounded supplied fact. The narrow grammar handles active/passive and common nominal forms, rejects non-factive allegations as support for concrete claims, coalesces duplicate full-name identities, and fails closed on unresolved name ambiguity. It uses no future oracle and does not replace the fail-closed LLM judge for pronouns, coreference, euphemism, or open-domain NLI. Full record: [`adr/0012`](adr/0012-deterministic-event-role-binding.md).

### D29 — Entity corrections are new valid-time identities, never backward rewrites (LIT-10) — **Accepted** (2026-07-13)
A split or re-merge ends its source identity rows and creates replacement identities at the correction bookmark. Aliases, relationships, state, and event participation are copied forward at that boundary, retaining the old model at earlier bookmarks. Splits require an explicit complete dependency assignment; merges require same-type sources and explicit resolution of conflicting event roles. Operations are atomic and audit-recorded. Schema-v2 backups forward-migrate only in restore staging, preserving LIT-24 recovery. Full record: [`adr/0013`](adr/0013-bookmark-effective-entity-corrections.md).

### D30 — Book type is advisory context, never a spoiler or data authority (LIT-9) — **Accepted** (2026-07-13)
After bounded segmentation, a deterministic provider-free classifier records a versioned profile for novel, anthology, drama, poetry, nonfiction, reference, or supported `unknown`; weak/conflicting evidence becomes `unknown`, and persisted signals use a closed content-free vocabulary. Classification never changes atoms, frontiers, receipts, visibility, or gates. Novel prompts and recap cache identity remain byte-identical; other profiles use neutral section-oriented extraction/recap language and hide or explain empty novel furniture while keeping grounded notes. Schema v4 persists the profile; existing stores migrate to an explicit legacy-novel marker, and schema-v2/v3 archives migrate only in restore staging. Full record: [`adr/0014`](adr/0014-book-type-detection-and-graceful-degradation.md).

### D31 — Re-reading starts an explicit epoch-bound pass and preserves memory (LIT-17) — **Accepted** (2026-07-13)
Backward paging moves the resume CFI while the bookmark remains the spoiler high-water for the current pass. A confirmed “start over” atomically rewinds only `bookmark`/`cfi` and increments a position epoch; every later position write is epoch-bound, so delayed reports and old tabs fail with 409 instead of re-advancing the reset pass. Extracted memory, durable receipts, ingest progress, costs, source, and atoms remain intact, and rereading performs no provider work. Existing catalogs and schema-v2/v3 archives acquire epoch zero additively in restore staging. Full record: [`adr/0015`](adr/0015-explicit-reading-pass-reset.md).

### D32 — Non-English sources keep Unicode identity under an English companion contract (LIT-23) — **Accepted** (2026-07-14)
The first declared EPUB content language is normalized and persisted in the atom manifest and schema-v5 book metadata; absent/malformed metadata is explicitly `und`, never guessed. NFC plus Unicode case-folding replaces accent-destructive identity normalization, and Unicode letter/mark tokenization brings Cyrillic, Greek, and uncased-script names into the same deterministic future-entity gate. A bounded legacy fallback recognizes selected Russian/CJK cast and structural labels without making language a destructive segmentation authority. Declared non-English sources request English derived prose while preserving names in source spelling; English/`und` prompt bytes and cache identities remain unchanged. Full record: [`adr/0016`](adr/0016-non-english-source-books.md).

### D33 — Hosted tenancy is structural and session-derived (LIT-37) — **Accepted** (2026-07-16)
Local/community and hosted modes share the spoiler-safe domain core but use different infrastructure adapters. Hosted data moves to PostgreSQL/pgvector and S3-compatible object storage; a durable leased worker replaces the in-process pool. Every tenant-owned and derived row carries `owner_id`, every repository lookup is owner-scoped from the verified session, foreign tenant identifiers are indistinguishable from missing ones, and PostgreSQL RLS is a second barrier. Caches, locks, jobs, objects, costs, and idempotency keys are tenant-scoped. Per-user provider keys use envelope encryption, are resolved just in time, and never enter job payloads, logs, or responses. Public launch is blocked on spoiler parity, cross-tenant coverage, secret-leak tests, quotas, backup/recovery, and migration drills. Full record: [`adr/0017`](adr/0017-hosted-multi-user-architecture.md); ordered work: [`product/professional-reader-roadmap.md`](product/professional-reader-roadmap.md).

### D34 — Hosted PostgreSQL is owner-composite, receipt-bound, and prefiltered before vector ranking (LIT-38) — **Accepted** (2026-07-16)
Hosted schema migrations are contiguous, checksum-verified, forward-only, and transactional. Every tenant or derived table has a non-null `owner_id`; book incarnation and owner flow through composite foreign keys, live uniqueness, indexes, jobs, costs, notes, provider settings, and audit foundations.
