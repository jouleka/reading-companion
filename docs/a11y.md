# Accessibility notes (LIT-16)

Target: **WCAG 2.1 AA**. LIT-16 is an audit + fix + document spike over the LIT-13 reader; the
"printed page & marginalia" design system stays intact — accessibility is woven into it, not bolted
on (the focus mark is a madder rule, not a browser-blue glow; the skip link is a slip that tucks off
the top edge). The a11y gate is enforced in tests via `jest-axe` scoped to the WCAG 2 A/AA rule tags
(`src/test-a11y.ts`) plus direct role/focus assertions.

## Fixed in LIT-16

- **Keyboard operability.** The primary page controls were mouse-only invisible `<div>`s and book
  spines were click-only `<div>`s. Both are now real `<button>`s: focusable, Enter/Space-activatable,
  labelled (`Previous page` / `Next page`; the spine's title+author is its accessible name). Page
  arrows still work globally, but the window handler now yields when a text control, the companion,
  or the confirm dialog holds focus (LIT-13 flagged this for LIT-16).
- **Landmarks & headings.** The reader is a `<main id="main">`; the companion is a labelled
  `complementary` (`<aside aria-label="the reading companion">`); the shelf is a `<main>`. The book
  title is the reader's `<h1>`; the companion's "Where you stand" is an `<h2>`.
- **Skip link.** `skip to the book` (targets `#main`) lets keyboard users bypass the running head.
- **Live regions.** The catch-me-up recap arrives asynchronously behind a persistent
  `aria-live="polite"` region, so a screen reader announces it (and the placeholder / gate-rejection
  copy) when it lands. Ingestion progress is a `role="status"`. The decorative ribbon is
  `aria-hidden` (its progress is already stated as text: "as of chapter III · 3 of 96").
- **The jump-confirmation dialog** (`JumpNote`) is a `role="alertdialog"`: focus moves onto the safe
  choice (`stay`) when it appears, and `Escape` dismisses to `stay`. It interrupts with a
  spoiler-relevant decision, so keyboard users must not be stranded behind it.
- **The start-over confirmation** uses the same alert-dialog contract and opens on “keep my place.”
  It explains both the rewind and the retained notes/costs, traps focus even while both actions are
  disabled during the request, treats Escape as cancel only when cancellation is safe, and announces
  server failures without losing the decision context.
- **Focus visibility.** A designed `:focus-visible` madder outline on every interactive element;
  the page arrows also un-hide their glyph on keyboard focus. Mouse clicks show no ring.
- **Reduced motion.** `@media (prefers-reduced-motion: reduce)` neutralises the companion's staggered
  settle, the spine hover-lift, the ribbon growth, and the skip-link slide.

## LIT-15 character graph (Cytoscape) — what shipped — **SUPERSEDED by §LIT-31**

> The standalone `CharacterGraph` this section describes was retired in LIT-31. Its real-slider,
> reduced-motion, measured-contrast, and keyboard-parity requirements carry forward. The canvas itself
> was ultimately removed: the current Codex relationship ledger is semantic DOM throughout.

Cytoscape renders to `<canvas>`, opaque to assistive tech, so the graph also exists as DOM. Shipped:

- **The canvas is `aria-hidden`**; a **structured DOM representation is ALWAYS present** — the cast as
  a `<ul>` (name + type) and the relationships as `Src — label — Dst` lines — visually-hidden
  (`sr-only`) under the canvas and shown in a **list/graph toggle** (`aria-pressed`). A screen reader
  always has the full cast + ties, read linearly; it inherits spoiler-safety from the clamped
  `/graph?bookmark=` payload (the accessible view and the canvas render the same data).
- **The `revealed_at` scrubber is a real slider** — a native `<input type="range">`, so `role="slider"`
  with `aria-valuemin/max/now` derived implicitly + an explicit `aria-valuetext="chapter N"`, labelled,
  arrow-key operable, bounded to the high-water.
- **Reduced motion** respected (cose layout `animate:false`; the scrim's entry is covered by the
  global `prefers-reduced-motion` reset).
- Contrast: canvas node/edge text and the scrubber all clear AA (measured).

**Routed to [LIT-28]** (honest gap — NOT shipped in LIT-15): interactive *roving-tabindex* node
traversal — Tab into the graph and arrow between characters, each node focusable with an
`aria-describedby` of its ties, for keyboard **parity with the canvas**. The current DOM equivalent is
a linear semantic list (screen-reader-navigable, not blocked), which is a legitimate baseline but not
the per-node focus traversal; that interactive layer is deferred.

## LIT-29 daily companion (piece 1) — what shipped

The memory redesign differentiates the companion into two surfaces and adds a return-gap welcome-back.
Accessibility decisions (an adversarial a11y pass drove the last two):

- **Sidebar live region preserved.** The companion's `aria-live="polite"` region (`.recap-region`) is
  still mounted **unconditionally** with only its contents conditional, so a screen reader announces
  whatever lands — now the tight **"right now" one-liner** rather than the full recap (which moved to
  the hero). The empty-first / filled-on-arrival pattern from LIT-16 is intact.
- **The flowing recap lives in the hero dialog**, not a live region. Character names in it render as
  **inert affordances** — `<span class="name-chip">` with no role, no handler, not focusable (the
  popup card is piece 2). The dotted **madder** underline (8.4:1 on paper) is a *discernible* non-color
  cue (1.4.1) — the earlier hairline underline at 2.06:1 was too faint; the chip text itself is 8.4:1
  (AA). They are deliberately kept out of the tab order until piece 2 gives them real semantics; a
  screen reader reads them as plain prose and the recap round-trips its full text (no dropped words).
- **Welcome-back framing is announced via the dialog's accessible NAME.** When the hero AUTO-opens
  after a ~4h return gap, the framing ("Welcome back — you left off in chapter X. The story so far.")
  is the dialog's `aria-label`, announced reliably when focus moves in on open. It is deliberately NOT
  a sibling `role="status"` region: a live region mounted **already-populated** is commonly dropped by
  screen readers, so its announcement would be unreliable. The visible `.welcome-back` banner is
  sighted-reader reinforcement only.
- **The auto-opening modal is a deliberate, documented decision.** Auto-surfacing the recap after a
  gap is a no-gesture change of context, so it is mitigated to the LIT-16 dialog bar: the reason is
  announced (above), focus moves onto the close control, everything behind is `inert`, **Escape**
  dismisses, a page turn dismisses, and it fires at most **once per gap** (localStorage-tracked) —
  never again until the next gap. A conscious trade (the "reader with a brain" re-orienting a
  returning reader), bounded so a keyboard/SR user is never stranded.

## LIT-30 live name cards (piece 2) — what shipped

Clicking a recap name-chip opens a `NameCard` popover (identity + ties). Accessibility (an adversarial
pass drove the focus-restore and nested-modal decisions):

- **The chips are now real `<button>`s** (were inert `<span>`s in piece 1) — keyboard-operable, in the
  tab order, accessible name = the character text, with the discernible madder dotted underline.
- **The card is a labelled dialog** (`role="dialog" aria-modal="true"`, `aria-label` = the character
  name): focus moves in on open; **Escape** and **click-away** (outside `mousedown`) close it; and
  focus **restores to the triggering chip** on close — the trigger is captured synchronously at render
  (before the fetch effect focuses the card root), so it is the chip and not the card, per WCAG 2.4.3.
  A **Tab focus-trap** keeps focus inside the card.
- **Nested-modal handling.** The card layers over the hero (itself a modal dialog). While the card is
  open the hero **yields the keyboard** to it (the hero's Escape/Tab handler returns early) AND the
  hero content is marked **`inert`**, so the two modals never coexist — the card is the sole active
  surface. One Escape closes the card (not the hero); a second closes the hero. The inert is cleared
  **synchronously in the close handler** (a reactive effect re-runs too late — `.focus()` inside an
  inert subtree is a no-op), so the focus-restore lands on the now-focusable chip. The **hero's own
  close** got the same treatment (synchronous trigger capture at render + synchronous un-inert), so
  closing the hero restores focus to its opener instead of falling to `<body>` (a pre-existing LIT-14
  gap the pass-2 review surfaced). NB the jsdom test suite is blind to `inert` focusability, so this
  timing is guarded by live-browser verification, not a unit test.
- **Walking the graph.** Each tie name is a chip that swaps the card to that character; focus follows
  to the new card content.
- **On screen.** The card is clamped to the viewport (left pinned inside; it opens upward from a chip
  low in the viewport) and its content scrolls (`max-height`). Contrast on the paper-deep leaf clears
  AA (name/close 13.7, meta + tie labels 6.4, madder tie chips 7.7); reduced motion neutralises the
  entry animation. **Known follow-up:** an event-typed tie endpoint (outside character/place/faction/
  object) is silently dropped from the ties list — harmless, absent from current data.

## LIT-31 the codex (piece 3) — what shipped

The codex is a full-screen two-leaf dialog (chapter breakdown · “People & connections” relationship
ledger · foot scrubber · layered name card) replacing the standalone LIT-15 graph. The initially
shipped focus-neighborhood canvas was itself replaced by the owner-approved editorial ledger in
`4e887f9`; the ledger keeps every name, directed statement, alias, chapter citation, register row, and
thread trail in semantic DOM. Its accessibility contract:

- **The dialog uses the proven `3ba2970` focus pattern, correct by construction:** the opener is
  captured **synchronously at render** (a lazy ref, before ReaderPage's modal-inert can steal focus),
  the focus/keyboard effect is keyed `[]` (reading `onClose`/card state via refs so the trigger is
  never re-captured), Tab is trapped inside the dialog, Escape closes, and on unmount focus restores
  to the opener — never `<body>` (WCAG 2.4.3). ReaderPage's `onClose` for BOTH full-screen leaves
  (hero and codex) calls the shared **`unInertGrid()`** helper to un-inert the `.reader-grid` children
  **synchronously before the leaf unmounts** — execution order, not effect order, is the guarantee
  (`.focus()` inside an inert subtree is a no-op; a reactive effect re-runs too late). This closes the
  routed LIT-30 finding: the retired `CharacterGraph` captured its trigger in a `[onClose]`-keyed
  effect and never un-inerted, so its close restored focus to `<body>`.
- **The ledger is the source of truth.** “People & connections” is a labelled section with a cast
  navigation landmark, search, focused-person article (`aria-live="polite"`), semantic lists of
  directed ties, explicit chapter-jump buttons, a filterable complete relationship register, and an
  ordered textual thread reader. It renders only the clamped `/graph?bookmark=` payload.
- **The cast index closes LIT-28 in the current ledger.** It is a roving list of real buttons: exactly
  one person is tabbable, ArrowUp/Down + Home/End move focus without changing selection, and
  Enter/Space/click selects the person and refreshes the live relationship article. Each button is
  `aria-describedby` by a hidden summary of that person's currently known ties. The roving index
  clamps when search or scrubbing shrinks the cast.
- **Focus is repaired when a shrink removes the focused option** (adversarial pass-1 HIGH, WCAG
  2.4.3): retiming to an earlier chapter unmounts later-revealed cast options; if the removed option
  held focus the browser would drop it to `<body>`, stranding a keyboard user behind the open
  dialog. The listbox tracks focus-within (a removal-blur has no `relatedTarget`, a real move does)
  and pulls focus onto the surviving roving option — and never steals focus parked outside the list
  (the scrubber, a chapter head).
- **`aria-current` tracks the selected person, not roving focus.** Moving through the index does not
  rewrite the relationship article until Enter/Space commits; this prevents arrow exploration from
  causing an unexpected context change.
- **Chapter navigation is native buttons:** each breakdown entry's head is a `<button>` that re-times
  the spread; the current chapter carries `aria-current="true"` plus a madder left-ribbon marker
  (color is not the sole indicator). Character names in summaries/events/new-here lines are the
  LIT-30 chip `<button>`s that open the card.
- **Nested name card:** the LIT-30 coordination carries over — while a card is open the codex leaves
  are `inert` and the codex yields Escape/Tab to the card's own trap; `closeCard` un-inerts
  **synchronously** before the card unmounts so focus restores to the chip that opened it.
- **The scrubber is unchanged** (native range = real `role=slider`, arrow-operable, `aria-valuetext`,
  bounded 1..high-water) and now drives the WHOLE spread from the codex foot.
- **Motion/contrast:** the ledger has no animated graph layout; the scrim entry inherits the global
  `prefers-reduced-motion` reset; every Codex pair reuses the LIT-16-measured AA palette (madder on
  paper 7.7–8.4, ink 14.9, ink-soft 6.4–6.9) — no new colors.
- **jsdom is blind to `inert` focusability** — focus-restore and trap behavior are verified in a real
  browser (the project's standing rule); the unit suite owns the ledger wiring, roles, roving
  tabindex, shrink-focus repair, and axe (WCAG A/AA) checks.

## LIT-54 install and offline controls

- Installation, connectivity, per-book save, and sign-out/erase actions are native buttons or status
  text with explicit accessible names; per-book actions are described by the corresponding book title.
- Offline and synchronization changes use polite live status text without moving focus or blocking the
  reading surface. Pending marks are labelled as queued rather than appearing silently saved.
- Touch targets retain the reader's 44-pixel minimum, visible keyboard focus, and existing AA palette.
- The sign-out control names its destructive offline consequence: it erases this owner's downloaded
  books and local reader state after the server logout attempt, including when that attempt is offline.

## LIT-57 Ask the Book

- The companion exposes Ask the Book only after at least one completed chapter. The question surface
  is a labelled modal dialog: focus enters the textarea, Tab remains inside, Escape closes, and focus
  returns to the opener. ReaderPage synchronously clears background `inert` before unmounting it.
- Busy and failure changes use one polite status region. An insufficient-evidence answer is ordinary
  text and never substitutes speculative prose.
- Each answer claim has native citation buttons with source-specific accessible names. The ordered
  source list includes the chapter title and bounded excerpt; activation closes the dialog and asks
  the reader engine to navigate to that EPUB href.
- Provider calls, token totals, payer, and known price are visible text. Unknown pricing is announced
  as unavailable instead of as a zero-dollar charge. The submit target retains the 44-pixel minimum,
  and the mobile dialog uses the dynamic viewport without obscuring controls.

## LIT-58 selected-text help and chapter closeout

- Explain, define, and translate-to-English are native 44-pixel action buttons beside the existing
  selection highlight/note controls. The selected passage remains visible as a semantic block quote.
- Selection results use a labelled, focus-trapped modal. Focus enters on close, Escape dismisses,
  background content is inert, and synchronous un-inert lets focus return to the exact action button.
  The source action restores the exact EPUB CFI rather than only the chapter start.
- Chapter closeout is an explicit companion button, never an auto-opening context change. Its modal
  presents semantic takeaway lists and source-specific citation buttons; activating one returns to the
  completed chapter evidence.
- Both surfaces use polite loading/error status, explicit insufficient-evidence prose, AA reader
  colors, dynamic-viewport mobile layouts, and visible provider/model/token/payer/price information.

## LIT-59 reader memory corrections

- “Correct this name” is a native button available only at the current correctable frontier. Its
  expanded state is programmatic, and the inline form preserves the Codex dialog's existing focus trap.
- Both fields have visible labels, native required and length constraints, and a polite actionable error.
  Save controls keep the reader's 44-pixel target and visible keyboard focus.
- Correction provenance is a semantic ordered list. Old and new names have screen-reader connective
  text, and the effective chapter is a native navigation button rather than a color-only marker.
- Scrubbing backward removes the future correction and its history together, without moving focus or
  announcing information beyond the chosen chapter.

## LIT-60 synchronized read aloud

- Read aloud is an `aria-expanded` disclosure containing native Play/Pause, Stop, previous/next
  passage, voice, and speed controls. Every action and select retains a 44-pixel mobile target.
- Speech state and unsupported/error outcomes use one polite status region. Ordinary reading remains
  available when browser speech is absent or fails.
- Foliate word marks drive the browser selection and reader scroll position, giving a visible current
  word without color being the only control-state signal. Stop and book exit clear that selection.
- Opening another full-screen reader surface pauses speech so two semantic contexts are not presented
  simultaneously. Speech is never auto-started.
- The source/cost explanation is visible text: on-device is claimed only for browser-reported local
  voices; other voices may use platform services; no Litlet provider, tokens, or paid request is used.
